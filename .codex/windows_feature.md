# WindowsアプリとLinux向けWeb UIの機能差

調査日: 2026-08-04
調査対象コミット: 1b7546a（タグ 1.0.8.7）
codex セッション ID: 019fcb14-24ec-7be1-8dcc-a509c2fea936

## 調査範囲と判定方法

Windowsアプリは、主に WPF の AmatsukazeGUI と、サーバーGUIを持つ
AmatsukazeServerWin を対象にした。Web UIは AmatsukazeWebUI の現行ページと、
それが呼び出す AmatsukazeShared / AmatsukazeServer のREST APIを対象にした。

「Windows版にあるがWeb UIにない」は、単に画面の配置が違う場合ではなく、
Linux上のブラウザから現行Web UIで同じ操作を実行できるかで判定した。
なお、Windowsのファイルダイアログ・エクスプローラー・タスクトレイなどは
ブラウザの制約またはデスクトップアプリの責務による差なので、コア機能の不足と
混同しないよう別分類にしている。

判定記号:

- A: Web UIに操作がない。ただし現行REST APIまたは共有APIで実現できる。
- B: Web UIだけでなく、現行REST API/DTOにも必要な入口がない。
- C: Windowsデスクトップやローカルファイルシステムとの統合機能で、ブラウザでは
  そのまま代替できない。
- D: 主機能はWeb UIにあるが、コピー、履歴、表示形式などの補助機能がない。

表中の「関連コミット」は、機能が初めて追加されたコミットとは限らない。
WPF側の実装、Web/API側の移植、または差分が明確になった変更を確認できる
コミットを記載している。

## 1. キュー画面

### 1.1 プロファイルと追加操作

WPFのキュー追加画面は、通常プロファイルだけでなく自動選択
（AutoSelect）も SelectableProfiles にまとめて表示する。
関連箇所は [QueueViewModel.cs](../AmatsukazeGUI/ViewModels/QueueViewModel.cs) の
SelectableProfile と、[SelectOutPathViewModel.cs](../AmatsukazeGUI/ViewModels/SelectOutPathViewModel.cs)
の初期化処理である。

現行の [Queue.razor](../AmatsukazeWebUI/Pages/Queue.razor) は
GetProfilesAsync だけを呼び出し、キュー追加・行内変更とも通常プロファイル名を
使っている。AutoSelectSettings.razor は存在するが、設定を編集するページであり、
キュー投入時に自動選択を選べることとは別である。

- Q-01 自動選択プロファイルのキュー投入/変更ができない。
- 関連コミット: e555888（Webの自動選択ページとキュー操作の追加）、
  4d4bd32（Web UI/APIの基盤）。
- REST側に自動選択の取得・評価機能があるため、まずWebの選択肢生成と
  追加/変更ダイアログを修正する種類の差分である。

WPFの [QueuePanel.xaml](../AmatsukazeGUI/Views/QueuePanel.xaml) と
QueueViewModel は、次の操作を持つ。

- 複製（ChangeItemType.Duplicate）
- Shift操作による元TSファイル削除（ChangeItemType.RemoveSourceFile）
- 追加中キューのキャンセル（CancelAddQueue）
- プロファイル設定をテキストでコピー
- 通常ロゴ生成と、SlimTSを使用する「ロゴ生成(TS解析あり)」
- 入力ファイルの場所を開く、出力先を開く

現行のWebコンテキストメニューには、ログ、再試行、プロファイル再適用、
キャンセル、削除、強制開始、通常ロゴ解析、カット調整、完了項目削除がある。
上記の複製、元TS削除、追加キャンセル、テキストコピー、エクスプローラー、
SlimTSロゴ生成は含まれていない。

Q-02からQ-04については、共有の ChangeItemType とRESTのキュー操作処理に
それぞれ対応する値/処理が存在する。さらに CancelAddQueueAsync は
AmatsukazeShared のクライアントAPIと /api/queue/cancel-add に実装済みである。
したがって、Web UIへの操作追加が中心になる。

- Q-02 複製: [QueueViewModel.cs](../AmatsukazeGUI/ViewModels/QueueViewModel.cs) の
  ReAdd と、[QueueRequests.cs](../AmatsukazeShared/Dtos/QueueRequests.cs) の
  Duplicate。関連コミットは 5964adf と 4d4bd32。
- Q-03 元TS削除: WPFの RemoveTS/ShiftRemove と、共有APIの
  RemoveSourceFile。元ファイルを消す破壊的操作なので、Web化する場合も
  確認ダイアログが必要である。関連コミットは d60bdff と 4d4bd32。
- Q-04 追加キャンセル: WPFの CancelAddQueueCommand と、
  /api/queue/cancel-add。関連コミットは 5964adf と 4d4bd32。

### 1.2 フィルタと追加ダイアログ

WPFは次のフィルタを持つ。

- 待機、処理中、完了、キャンセル、失敗/失敗予測などの状態
- 優先度
- 日時範囲
- ワンセグを隠す
- 入力、出力、プロファイル、サービスなどの検索対象を選ぶ検索文字列

Webの [Queue.razor](../AmatsukazeWebUI/Pages/Queue.razor) は検索対象と、
待機・保留・処理中・キャンセル・完了の状態をクライアント側で絞り込むが、
失敗状態を選択するボタン、優先度フィルタ、日時範囲、ワンセグ非表示の
コントロールがない。失敗件数自体は表示されるため、状態の表示とフィルタの
不一致もある。

共有の QueueFilter には States、Search、SearchTargets、DateFrom、DateTo、
HideOneSeg があり、RESTのサーバー側フィルタも実装済みである。
Webページは現在 GetQueueAsync() を無条件で呼び、取得後に一部だけローカル
フィルタしている。

- Q-05 日時範囲とワンセグ非表示はAPI対応済みのA。
- 失敗状態と優先度フィルタはWeb側のUI/フィルタ実装が必要なA。
- 関連コミットは 9e9c76e（キュー検索）、53f0bce（優先度操作）、
  e555888（キュー状態切り替え）。

WPFの SelectOutPath.xaml には、次の追加補助機能がある。

- 出力先履歴の選択
- 出力先をデフォルト値に戻す
- 「キューを凍結して追加」
- 追加後にキューを一括投入する設定

WebはUI状態に保存された直前のプロファイル/出力先を事前入力するだけで、
履歴のドロップダウン、デフォルト復帰、追加前のキュー凍結がない。
キュー追加処理も AddQueueAsync のみを呼び出している。

- Q-06 「キューを凍結して追加」は、WPFが追加前に PauseEncode を行う機能。
  関連コミットは 79547cd と 4d4bd32。
- Q-07 出力先履歴は 8bbfd47 が関連する。Webは最後に使った値を保持する
  ため完全な初期値機能がないわけではないが、複数履歴の選択とデフォルト
  復帰がない。

### 1.3 ロゴ生成、ファイル操作、表示形式

通常の手動ロゴ解析はWebにもあり、解析範囲、しきい値、最大フレーム数、
採用/破棄まで実装されている。ここはWindows版との差分に数えない。

一方、WPFには通常解析とは別に SlimTS を作成して解析する操作がある。
QueueViewModel が logo analyze 用プロセスに slimts オプションを渡し、
LogoAnalyzeViewModel が TsSlimFilter を利用する。
Webの LogoAnalyze.razor に SlimTS指定や同等のREST要求はない。

- Q-08 「TS解析あり」のロゴ生成は、通常ロゴ解析とは別機能である。
- 関連コミットは 37366ad（SlimTSロゴ解析を含むWPF実装）と
  ece1b7d（Webのキュー自動更新/ロゴ解析）。
- 現状は必要なサーバーAPIもWeb向けに公開されていないためBとした。

WPFでは、キューのコンテキストメニューから入力ファイルを
EXPLORER.EXE /select で開き、出力先もエクスプローラーで開く。
ブラウザでサーバー側のパスを開く同等操作はできない。

- Q-10 はブラウザのローカルファイルシステムに対するC。
- 入力ファイルの場所を開く機能に関連するコミットは 63e0d81、
  出力先を開く機能に関連するコミットは 74130bc。

WPFは ListStyle 設定で、詳細表・簡易表示などのキュー表示テンプレートを
切り替える。Webは表形式1種類である。

- Q-11 は主機能ではなく表示UXのD。関連コミットは b90dedd と 4d4bd32。

WPFはファイル/フォルダをキュー画面へドラッグ&ドロップできる。Webの
PathSuggestInput はサーバー上のパス候補を入力するもので、Linux上の
ブラウザからクライアントPCのローカルファイルをWPFと同じ形で投入する
機能ではない。

- Q-12 はブラウザとローカルファイルの境界によるC。
- WPFのファイル追加・出力先選択に関連するコミットは 79547cd、
  Web UI基盤は 4d4bd32。

## 2. ログとコンソール

### 2.1 CSV出力

WPFの [EncodeLogPanel.xaml](../AmatsukazeGUI/Views/EncodeLogPanel.xaml) と
EncodeLogViewModel には CSV出力のコンテキストメニューと保存ダイアログが
ある。チェックログ側も同様にCSV出力を持つ。

共有APIには GetEncodeCsvAsync と GetCheckCsvAsync があり、RESTにも
/api/logs/encode.csv と /api/logs/check.csv がある。Webの
EncodeLogs.razor / CheckLogs.razor はログ一覧と詳細表示を持つが、CSV出力
ボタンやダウンロードリンクを表示していない。

- L-01 はAPI実装済みのAで、Webへのボタン追加で対応可能。
- WPFログ画面の実装に関連するコミットは 184f2df、
  Web UIの基盤/APIは 4d4bd32。

### 2.2 サーバー・クライアント・追加処理ログ

WPFのメイン画面には、次のログ/コンソール画面がある。

- サーバーのライブログ（ServerWindow）
- クライアントログ（ClientLogPanel）
- サーバーが保持するログファイル（LogFilePanel）
- キュー追加処理専用のコンソール（AddQueueConsolePanel）
- 個別エンコードタスクのコンソール（ConsolePanel）

Webの Console.razor は個別タスクのコンソール表示に対応しているため、
タスクコンソール全体を未実装とはしない。しかし、Logs.razor は
エンコードログとチェックログへのリンクだけで、サーバー/クライアント/
キュー追加ログを参照するページはない。MainLayoutのMessagePanelも直近の
通知を少数表示するもので、ログビューアの代わりにはならない。

共有の ConsoleView DTO には Consoles と AddQueueConsole のフィールドが
あるが、現在の RestStateStore のスナップショットでは ConsoleView が
公開されず、Web向けの追加処理コンソールAPI/ページもない。

- L-02の追加処理コンソールはB。DTOの残骸を再利用できる可能性はあるが、
  現行RESTの公開契約としては未提供である。
- サーバー/クライアントのライブログは、Windows GUI内部の状態・ログファイル
  へのアクセスをWebへ公開していないためB/Cとした。
- 個別タスクコンソールは b494508 でWebに追加済みなので、そこは差分から
  除外した。WPFのコンソール/スクリプト実行周りの関連コミットは 378703f。

WPFのログ・コンソールには、選択行のコピー、オートスクロール、
ログ項目の豊富なソート列、詳細表示がある。Webはタスクコンソールを表示
できるが、WPFのコンテキストメニューに相当するコピー操作はなく、
ログ一覧のCSV以外の補助操作も少ない。

- L-03はD。ログそのものの取得と、ログ操作の補助UIを分けて扱うべきである。
- 関連コミットは 378703f と b494508。

## 3. スリープ、サーバー操作、MakeScript

WPFには SleepCancelWindow と SleepCancelViewModel があり、エンコード後の
スリープ・休止・シャットダウンまでの残り時間を表示し、その間にキャンセル
できる。Web/共有APIには CancelSleepAsync と /api/system/cancel-sleep が
あるが、現行Webページから呼び出す箇所やカウントダウンモーダルがない。

- S-01はAPI実装済みのA。
- 関連コミットは 7c40f96（エンコード後スリープ）と 4d4bd32（Web/API基盤）。
- Webの終了動作を追加する場合、Linux上で実際に利用できる電源操作かどうか
  もサーバー側で確認する必要がある。

WPFの MakeScriptPanel には「Amatsukazeサーバを停止」ボタンがあり、
MakeScriptViewModel.StopServerCommand からローカルサーバーを確認付きで
停止する。Webの MakeScript.razor はバッチファイル生成、プレビュー、
ダウンロードを実装しているが、サーバー停止操作を持たない。
共有APIの EndServerAsync と /api/system/end は既にある。

- S-02はAPI実装済みのA。
- 関連コミットは 378703f と 4d4bd32。
- Webへ追加する場合も、サーバー停止は破壊的操作なので確認を必須にする。

WPFのバッチ生成結果画面には生成ファイルパスをクリップボードへコピーする
補助操作がある。Webは生成物をダウンロードするリンクはあるが、パスの
コピー操作はない。

- MakeScriptの主機能（local/remote、bat/sh、NAS、Wake On LAN、直接実行、
  プレビュー）はWebにあるため不足とはしない。
- 生成パスのコピーだけをDとして残す。関連コミットは 378703f と 4d4bd32。

## 4. プロファイルと設定

### 4.1 プロファイル設定の補助機能

Webの ProfileSettings.razor は、プロファイルの作成、名前変更、削除、
適用、主要なエンコーダ/フィルタ/リソース設定を実装している。したがって、
プロファイル編集そのものを未実装とはしない。

ただしWPFの [ProfileSettingPanel.xaml](../AmatsukazeGUI/Views/ProfileSettingPanel.xaml)
には次の補助表示/操作がある。

- プロファイル設定をテキストとしてクリップボードへコピー
- 設定の組み合わせに応じた SettingWarningText の警告表示
- MPEG2/H.264のビットレートサンプル表（18/12/7Mbps）
- リソース設定のコピー、貼り付け、使い方
- リソース設定の詳しい説明とCPUアフィニティ操作

Webにもビットレート設定、リソース表、CPUアフィニティ設定はあるが、
サンプル表、コピー/貼り付け/使い方ボタン、警告文の表示はない。
ブラウザのClipboard APIを利用すれば一部は移植可能である。

- P-01/P-02はD（設定値の欠落ではなく補助UXの欠落）。
- プロファイル設定テキスト出力の関連コミットは f477e14、
  WPFの設定画面一式は 184f2df、Web基盤は 4d4bd32。

### 4.2 一般設定

WPFの SettingPanel は、Windowsアプリのテーマ（自動/標準/ライト/ダーク）
とアプリフォントサイズを選択できる。Webはブラウザ/CSSのテーマを使い、
この2項目を設定するページはない。

また、WPFのパス入力には個別のクリアボタンやWindowsのファイル選択/
ドラッグ&ドロップがある。Webのパス入力はサーバー側パス候補を扱い、
値を手動で空にすることはできるが、WPFと同じ専用ボタン・ローカル選択
ワークフローはない。

- T-01はデスクトップ表示設定のC/D。関連コミットは 3ca1068 と 4d4bd32。
- T-02はパス入力の補助UXとしてC/D。関連コミットは 79547cd と 4d4bd32。
- Windows専用パスやWindows専用エンコーダ設定がLinux Web UIに表示されない
  箇所は、意図的なプラットフォーム分岐であり、今回の不足には数えない。

## 5. サービスとロゴファイルの登録

WPFの ServiceSettingPanel は複数の .lgd ファイルをWindowsのファイル
ドラッグ&ドロップで受け取り、一括インポートできる。

- Amatsukaze拡張形式はファイル内のServiceIdから対象サービスを決め、
  未登録なら自動作成する。
- AviUtl形式は解像度を一度確認し、複数ファイルをまとめて変換・登録する。

Webの Services.razor は InputFile 1ファイルのアップロードで、multiple指定
やD&Dの一括受付はない。AviUtl形式の幅/高さ入力はWebにもあるため、
解像度確認そのものは不足とはしない。

現在のRESTの /api/services/logo は拡張LGDのサービス自動作成やAviUtl形式の
変換を処理できる。しかしWeb側はサービス選択を必須にしているため、
サービス未選択のまま拡張LGDをアップロードして自動登録するWPFの流れには
到達できない。

- V-01は、単一ファイルならWebで可能だが、一括D&Dとサービス自動登録の
  入口がないC/A。
- WPF側の関連コミットは 3cb363d、Web/API基盤は 4d4bd32。

## 6. Windowsデスクトップ固有の機能

これらはLinux上のWeb UIに同じ機能を実装するより、Web UIの実行モデルが
異なることを明示しておくための項目である。

### 6.1 接続先の切り替え

WPFの ConfigWindow は接続先サーバーのIPアドレスとポートを変更し、
接続先を切り替える。MainWindowには接続先変更操作がある。
Web UIは通常、現在アクセスしているサーバーのREST APIを使用するため、
画面から別サーバーのIP/ポートへ切り替える設定はない。

- W-01はWindowsクライアントの接続管理機能でC。
- 関連コミットは 184f2df と 4d4bd32。
- Webで実現するなら、許可する接続先・CORS・認証情報の扱いを含めて
  別機能として設計する必要がある。

### 6.2 タスクトレイとタスクバー

WPFには次のデスクトップ連携がある。

- サーバーを最小化するとタスクトレイへ格納
- キュー状態に応じたタスクトレイアイコン切り替え
- タスクバーのエンコード進捗表示
- タスクトレイメニューからの表示/終了操作

ブラウザタブにはWindowsタスクトレイやタスクバー進捗へアクセスする
同等APIがないため、Web UIの機能差としてはCに分類する。

- W-02の主な関連コミットは 9b80722（キュー状態によるトレイアイコン）と
  cbd55de（最小化時のトレイ格納）。

### 6.3 起動モードとローカルGUI

AmatsukazeGUIは client、server、standalone の起動モードを持ち、
WPF画面、ローカルサーバー、別プロセスのサーバー接続を組み合わせる。
Web UIは既に起動されたサーバーへブラウザで接続するため、同じ起動モード
切り替えは持たない。

- W-03はWeb UIに移植する対象というより、Windowsアプリ固有のC。
- 関連コミットは 9aae033（standalone）と 184f2df。

## 7. Web UIに既に実装されているため、差分に数えなかったもの

調査時点で、次の機能はWindows版とWeb版の両方に相当する操作があるため、
今回の「未実装」一覧から除外した。

- プロファイル、自動選択設定、サービスの追加/削除/編集
- DRCSの未マッピング/全件表示、文字の追加・変更・削除、外字画像表示
- 通常の手動ロゴ解析、解析結果の採用/破棄
- カット調整、再投入、カット設定
- キューの一時停止、エンコーダ停止、完了後動作、並べ替え、優先度変更
- エンコードログ/チェックログの一覧と個別詳細表示
- 個別エンコードタスクのコンソール表示
- MakeScriptの主要な生成機能、NAS/Wake On LAN/EDCB直接実行
- サーバー情報、バージョン、プラットフォーム、ディスク空き容量の表示
- 一般設定の主要な保存項目

特にカット調整は、通常モード対応の 7c62c24 や一時フォルダ削除の
a6d3f06 がWeb側にも反映されているため、Windows版だけの機能とは
判定しなかった。また、Webの常時表示ディスク設定を削除した d882dc9 は、
情報ページで常にディスクを表示する設計へ変更したものなので、単純な
未実装として扱っていない。

## 8. Git履歴からの確認結果

主に次の履歴・差分検索を行った。

- git log --all -- AmatsukazeGUI AmatsukazeWebUI
- git log --all -S<機能名> -- <WPF/API/Webの関連ファイル>
- Web/APIの基盤と、WPF側だけに追加された後続コミットの比較

Web UIの基盤は 4d4bd32、ページ一式の初期実装は ebe447a、
キュー追加・自動更新・ロゴ解析などの拡張は ece1b7d、
個別タスクコンソールは b494508 である。その後もWeb側へ移植された
機能は多数あるため、WPFにだけ変更があるコミットをそのまま不足とは
せず、現行ファイルも確認した。

差分判定で特に参考になった履歴は次の通り。

- 9b80722: Windowsタスクトレイアイコンの状態切り替え。Webには該当する
  デスクトップ連携がない。
- 74130bc: キューから出力先を開く操作。現行Webキューにない。
- 3cb363d: LGD追加機能を拡張。RESTは一部共通化されたが、Webの一括
  InputFile/D&D操作は移植されていない。
- f477e14: プロファイル設定のテキスト出力。WPFにはあるがWebにはない。
- 8bbfd47: エンコード後動作と出力先履歴。Webは直前値の保持までで、
  履歴選択はない。
- 7c40f96: エンコード後スリープ。キャンセルAPIはあるがWeb画面がない。
- 37366ad: SlimTSを使うロゴ解析を含むWPF実装。現行Webには同じ入口がない。
- d882dc9: Webの常時表示ディスク設定を意図的に削除した変更。情報ページの
  ディスク表示へ設計変更済みなので不足から除外した。
- 7c62c24、a6d3f06: カット調整関連のWPF変更だが、現行Webにも対応する
  機能/APIがあるため不足から除外した。
